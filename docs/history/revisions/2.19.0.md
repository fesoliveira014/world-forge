# Atlas 2.19.0 — temporary zoom terrain detail

The **Zoom detail** toggle adds bounded visual subdivisions near the view centre
in Natural globe and Shaded relief globe/map views. The original generated mesh
remains the minimum detail, with no camera-driven simulation, storage requests,
or saved-world changes. Existing snapshots work immediately. Saving stays manual.

Saved heights and one-ring slope normals supply a constrained interior terrain
curve. The effect is deliberately modest in top-down Natural views, which already
use smoothed lighting. It does not increase climate, biome or riverbank texture
resolution and does not create additional physical cells.

Original face edges, wet surfaces, shores and entire river-intersecting faces stay
fixed. New geometry is prepared cooperatively; the current complete surface stays
visible until a replacement is ready. Short geometric transitions and selection
hysteresis reduce popping. Zooming out removes only the added display detail.

## Resource limits

The installed patch has at most 32,760 vertices and can replace faces in at most 32
physical batches. One replacement generation may coexist during preparation. A
single additional draw renders the merged patch; masked original batches share
their unchanged terrain attributes and material. The river protection index shares
the existing compact river packets and adds metadata proportional to network size.

On the retained AETHER river fixture, 83,541 segments required 1,258,080 bytes of
index arrays (about 1.20 MiB). Cooperative construction took 335 ms wall time across
128 task yields, with a measured maximum uninterrupted slice of 5.45 ms. 10,000
geographic queries averaged 10.5 segment checks rather than scanning the full
network. These cloud measurements are not hardware-GPU performance claims.

On the retained 2,621,442-cell world, a close globe view added 6,372 vertices over
59 physical faces, accounting for 22,770,496 extra bytes (21.7 MiB), including
20,533,624 bytes of river-index metadata. Returning to the wide view released all
extra buffers. The conservative tiny-batch check reduced wide-view selector CPU
time from 273.2 ms to 9.0 ms at the same camera, with zero candidates in both runs.
Close-view selection dropped from 61.3 ms to 29.2 ms with identical output.
These timings measure selection work, not rendered frame time.

Full detail readiness is slower than selection alone: the largest-world QA step
from wide-ready to close-ready took about 25.5 s, and re-enabling detail took
26.3 s, including river-index preparation, scheduled frames and the measurement/
screenshot harness. These are observed end-to-end test steps, not isolated
production interaction timings. Existing physical terrain remains visible during
preparation; this first release does not promise immediate extra detail on very
large river networks.

The complete world's existing memory is unchanged. Reported buffer estimates
exclude JavaScript objects, temporary construction scratch, worker memory and
graphics-driver overhead. Details and limitations are in
[the implementation notes](../design/implementation-2.19.md).

## Validation

- 342 tests pass, including 34 focused zoom tests covering reconstruction,
  topology, selection, rivers, geometry/material interpolation and lifecycle.
- TypeScript, repository formatting and changed-file ESLint pass. The unrelated
  existing legacy TileLod/TileDensity lint errors remain outside this change.
- Browser comparisons use the same frozen 84c53d9 snapshots and cameras. They check
  immutable terrain/river/bank hashes, supported and bypassed styles, coast/lake/
  river views, poles/dateline, camera motion, toggle disposal and physical picking.

All 30 small browser captures completed without rendering errors and retained
identical terrain, river, flow-phase and bank-atlas hashes. Disabling zoom detail
returned exactly identical pixels in the tested globe and flat-map views.
The [browser measurement report](../../observations/measurements/zoom-detail-browser-2.19.0.json)
records the comparisons, lifecycle checks and maximum-resolution observations.

The retained maximum-resolution snapshot has pre-existing gaps in some rendered
river strips. Exact-camera on/off captures confirm those gaps are unchanged by
zoom detail; this release does not repair that older network presentation.

Application version is 2.19.0; generator identity remains 2.17.1.
