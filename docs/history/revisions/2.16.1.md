# Atlas 2.16.1 — rivers and globe motion

This patch fixes two rendering regressions introduced by the paged viewer. It does
not change terrain generation, drainage, sediment evolution, or saved physical
state. Existing `atlas-view/v2` snapshots open without regeneration; 2.16.0 recipes
remain accepted.

## River coverage and placement

The previous overlay reader traversed geographic bins south to north and spent its
segment budget on every bend of the first reaches. Later regions could receive no
river geometry. The reader now selects complete visible reaches across geographic
bins, ranks flow within each bin, and uses the remaining budget for bend detail.
Regional zoom restores the saved curve detail as the visible feature count falls.

New snapshots include an optional per-bin flow ranking. Older snapshots stream
small reference and discharge pages to construct bounded rankings. That fallback
retains at most 65,536 small candidate records across at most 512 cached rankings;
a query considers at most 32,768 candidates. These JavaScript records are additional
to the existing page cache. The overlay packet remains capped at 8,192 total
segments, shared among enabled line layers; the UI requests 8,000.

River endpoints now sample the same continuous terrain surface used by display
tiles and retain higher hydrological water levels. Cartographic ribbons draw over
coarse display triangles, with explicit fragment clipping at the globe horizon and
map boundaries. Physical channel width and the screen-space width cap are retained.

A pre-patch 2.16.0 snapshot, with no ranked sidecar, was queried before
and after with the same seed, saved physical data, viewport, and 8,192-segment cap:

| Latitude band | Before | After |
| ------------- | -----: | ----: |
| 90–60° S      |    976 |   241 |
| 60–30° S      |  6,643 | 1,652 |
| 30–0° S       |    573 | 1,313 |
| 0–30° N       |      0 | 1,665 |
| 30–60° N      |      0 | 3,079 |
| 60–90° N      |      0 |   242 |

Both queries returned exactly 8,192 segments. This measures geographic coverage,
not identical curve detail. Broad views can still omit minor reaches when the
budget is exhausted.

## Stable globe detail

Previously, every camera update rebuilt tile selection from the roots. A 4° globe
rotation could replace a visible detailed tile with its coarser ancestor even
while the detailed tile was resident. The selected tile tree now persists across
camera changes. Visible detail stays resident during rotation and panning;
offscreen groups can coarsen, and actual zoom-out uses a separate lower threshold.
The tree remains balanced across tile edges, poles, and the longitude seam.

New child tiles interpolate from their parent for 240 ms. Shared edges stay fixed
and procedural terrain texture coordinates remain geographically anchored.
Categorical layers retain discrete class colors. Rendering returns to idle when
the transition and camera motion finish.

The existing limits remain 64 active tiles, 128 resident tiles, four concurrent
tile requests, and 32 MiB of retained tile CPU/GPU data. The byte accounting now
reserves temporary transition arrays as well. Overlay and shared texture storage
remain separately reported.

## Validation

Regression coverage includes geographic river selection in legacy and newly
indexed snapshots, complete reaches under tight budgets, restoration of bend
detail on regional zoom, terrain draping, dateline widths, and horizon clipping.
LOD tests cover a full globe rotation, asynchronous loading and eviction, deep map
pans, explicit zoom-out, all edge-stitch masks, successive transitions, exact
transition completion, and preserved shared edges.

Validation commands: `npm test` passed all 198 tests; `npm run typecheck` and
`npm run format:check` passed. The private release uses `npm run build:local`.

The [saved-world coverage comparison](../../observations/measurements/river-coverage-2.16.1.json)
records the before/after query above. Actual WebGL pixel readback passed all 14
[river horizon and map-edge cases](../../observations/measurements/river-horizon-gpu-2.16.1.json):
front-facing rivers rendered, back-facing rivers produced zero visible pixels,
and dateline/edge cases produced no pixels outside their expected map regions.

The [browser navigation report](../../observations/measurements/browser-render-2.16.1.json) passed
30 stages covering small and large globe rotations, five zoom steps in each
projection, map panning, seasons, and Natural/Shaded relief/Ink atlas styles.
Rotations retained visible detail, transitions completed, the natural view stopped
drawing at idle, and no browser errors occurred. Peak observed residency was
128 tiles and 19,135,488 accounted tile bytes, with at most 64 active tiles and
four requests. These checks used system Chromium with SwiftShader in the cloud
environment; they validate rendering behavior and bounds, not hardware-GPU frame
rate.
