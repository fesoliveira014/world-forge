# Atlas 2.18.1 — globe cell-grid visibility

At some globe angles, the cell grid disappeared at a zoom where nearby views
still showed it. Crossing a pole expanded the rectangular longitude query to
the entire latitude band. Off-screen edges then exhausted the bounded grid
packet, incorrectly triggering the zoom-in cue. Local refinement can make this
easier to trigger by adding more edges.

## Changes

- Globe grid queries use a spherical camera footprint, including relief near the
  horizon. Only edges intersecting that footprint consume the grid budget.
- Grid edges are clipped as spherical paths, including arcs that enter the view
  even when both endpoints are outside it. The traversal follows the saved mesh,
  including locally refined cells, and remains bounded.
- Raised globe grid lines use a camera-to-point globe-occlusion check rather than
  a radial-facing cutoff. This keeps visible elevated edges at the limb while
  hiding the far side.

The complete grid still asks for a closer view if its viewing footprint exceeds
the packet budget. Map-grid behavior, terrain detail, river assets, shared display
buffers and manual saving are preserved. Application version is 2.18.1; generator
identity remains 2.17.0. Saved worlds need no regeneration.

## Verification

All **296 automated tests** pass, along with typecheck, formatting and production
build. New coverage uses an independent Cartesian clipping oracle, rotated
footprints at both poles and the dateline, a locally refined polar mesh with
493 visible edges, empty footprints inside a coarse cell, invalid requests and
bounded dense-view fallback. Camera-ray tests cover raised surfaces at different
distances and zooms.

Browser comparisons used the same saved worlds and cameras before and after in
Chromium with SwiftShader software graphics:

The small-world sweep includes equatorial, northern, southern and dateline views.
The maximum-world sweep includes the equator, a footprint crossing the north pole
and the pole itself. Their grid-off terrain screenshots are pixel-identical to
2.18.0. A separate WebGL shader probe restores the raised line beyond the base
limb while preserving the coarse front chord and hiding both far-side controls.
The maximum snapshot verifies rendering at that size; local-refinement topology
is exercised separately by the automated refined-mesh test.
