# Atlas 2.19.1 — persistent physical cell grid

The previous grid renderer rebuilt a viewport-specific overlay after camera
movement. Its 8,000-segment budget was shared with other enabled line overlays;
when the complete visible grid exceeded that budget, it discarded every grid
line and displayed a zoom-in cue. This could hide the whole grid even on a
10,242-cell world. Asynchronous queries could also show stale coverage while the
camera moved.

## Behavior

Cell grid now has a dedicated rendering path. Enabling it loads the complete
physical edge network in stable indexed batches, with loading progress. Loaded
batches stay resident when the grid is hidden, so repeated toggles need no reload.
Camera movement reuses the same geometry. No zoom-out threshold or other
overlay's line budget can clear it.

Grid loading redraws at a small number of progress milestones instead of
rendering the entire world for every packet. Loading-label updates do not redraw
the canvas. Automatic rotation and background flow animation pause during grid
preparation; manual camera controls still redraw immediately. The line color and
opacity match the earlier full-grid renderer, keeping dense grids from washing
out the terrain.

The grid follows the saved dual-cell topology, including manual regional
refinement. It does not draw temporary visual zoom-subdivision triangles or
change the physical world. Existing saved worlds work without regeneration;
generation and manual saving remain unchanged.

## Data and rendering

The reader uses bounded ranges of saved physical edges and deduplicates their
corner vertices inside each packet. Directions and heights remain Float32, with
Uint16 indices and at most 8,192 edges per packet. Wet lake corners use the saved
water-surface level. No new snapshot fields, whole-world restoration, resolution
recomputation or disk cache are introduced.

A separate worker loads grid packets without queuing behind terrain, river or
inspection requests. Turning the grid off pauses additional loads. Completed
preparation releases the worker and its page caches; changing the world discards
the old grid and ignores late responses.

On the globe, geometry references the stored packet arrays directly and applies
relief in the vertex shader, avoiding a second CPU position array. All batches
share one material. Conservative frustum and globe-occlusion culling operate on
the current camera. Wide batches that cannot safely be rejected remain visible;
the existing line shader handles precise globe occlusion.

The flat map reuses ordinary indexed vertices and splits seam/pole-crossing
edges where needed. Projection and relief changes can rebuild the display from
resident packets without reading the physical grid again. Only the current
display representation is retained.

## Memory and verification

Persistent availability uses more memory than the old capped overlay. The grid
has one retained packet asset plus GPU buffers; projected map positions and
seam vertices are additional. Buffer diagnostics include these costs, while
JavaScript objects, temporary construction scratch and driver overhead remain
outside the estimates. Turning the grid off retains it for fast reuse; closing
or replacing the world releases it.

- All 363 tests pass. New coverage exercises full edge coverage, refined grids,
  lake surfaces, worker transfers, independent reader lanes, loading/retry/
  cancellation, shared buffers, projection seams and poles, and conservative
  culling checked against an independent ray/sphere oracle, progress scheduling,
  and display changes independent of loading-label updates.
- TypeScript, repository formatting and changed-file lint pass.
- The 10,242-cell fixture retains all 30,720 physical edges. Its globe grid uses
  462,880 bytes of source arrays, no extra CPU position arrays, and 462,880 bytes
  of estimated GPU buffers: 925,760 bytes accounted in total. Its map adds
  projected vertices and seam pieces for a total of 1,199,832 bytes.
- Browser checks retain all 45,141 edges after regional refinement and
  verify unchanged grid-off terrain pixels. Camera, toggle, style, layer, season
  and projection changes reuse the grid without new physical-grid reads.
- The 2,621,442-cell world retains all 7,864,320 physical edges in 960 batches.
  Its globe grid accounts for 118,429,440 bytes of source arrays and the same
  estimated GPU allocation, about 226 MiB combined. Wide-view culling draws
  516 batches; the tested close-up draws 24. Hiding the grid draws none while
  preserving the cached buffers. The dedicated worker is released at completion.
- A fresh maximum-world first enable completed in 67.7 seconds, including GPU
  completion, with normal rendering in the cloud software-GPU environment.
  It made 961 grid requests (one manifest and 960 batches) and reported no errors.
  Subsequent camera movement and toggles do not repeat this preparation.

The compact browser evidence is recorded in
[`measurements/persistent-grid-browser-2.19.1.json`](../../observations/measurements/persistent-grid-browser-2.19.1.json).

Browser measurements use Chromium with SwiftShader in this cloud environment.
They verify geometry and cache behavior but do not represent hardware GPU frame
rates. The grid remains a dense line network when millions of cells are smaller
than screen pixels; persistent availability does not make each cell individually
readable at that scale.

The flat-map shader also clips against geographic latitude before height shear,
keeping raised polar edges visible. Exact signed-zero dateline endpoints are
drawn on both map borders without invalid seam coordinates.
