# Atlas 2.17 — fixed physical detail and connected rivers

Atlas now displays the generated physical mesh at every camera distance. Loading
uses fixed spatial batches, but rotating, panning and zooming do not replace
vertices, simplify the terrain or request higher-resolution material tiles.

## Terrain

The reader extracts the original physical triangles and per-cell material fields
directly from existing snapshots. Shared vertices include their complete incident
faces when computing normals, so batch boundaries retain the same slopes and
lighting. Natural, Shaded relief and Ink atlas use the same compact physical data.

Categorical layers use the saved dual cell polygons with flat category ownership.
They are not nearest-neighbor samples of a display grid. Map projection preserves
compact attribute normalization, paired 16-bit scalar fields and category owners
when it creates dateline or polar copies.

Style, relief and projection changes reuse retained render packets. A different
world, layer or season requests the corresponding physical fields. Detailed
loading progress remains visible while the full mesh is prepared.

## Rivers

River preparation follows complete saved channel chains above the selected flow
threshold. It retains curve samples, shared downstream phase, discharge widths,
connected bevel joins, seasonal activity and source categories. Lake and ocean
endpoints follow the previous receiving-water anchoring rules. Other overlay
toggles no longer consume a shared river segment budget.

Very wide strokes are limited where a bend cannot accommodate them. The limit
comes from the saved curve's radius with a gradual width transition, before
transport batching; it does not depend on the camera or remove any curve samples.
Dense sampling uses a wider geographic neighborhood when Float32 coordinates
cannot resolve the immediate turn. Straight courses and safely narrow strokes
keep their original widths, and the width slider respects the same bend limit.

Adjacent spans share their inner corner and have a single outer bevel. Incoming
and outgoing path guides keep these joins consistent across packet boundaries,
avoiding the former overlapping translucent triangles. Shared flow phase, source
colors and seasonal activity remain attached to the original curve samples.
Short lake connectors still follow their coarser saved courses and can appear
broader than neighboring rivers constrained by tight bends.

Separate left and right bank records paint a stable, mipmapped bank texture along
the same channel paths. Oxbows retain wet, frozen and dry appearances. Delta
habitats remain surface shading, consistent with the earlier river design.

The river reader caches one season/threshold variant and drapes each prepared
batch once against the saved physical surface. Each curve point supplies a nearby
physical cell, avoiding repeated global nearest-cell searches. Changing the
season or flow threshold cancels an obsolete river worker before starting the
latest request.

## Storage and memory

Existing saved snapshots remain readable without regeneration or migration.
Generation still creates an unsaved working world, and only **Save world** adds
it to the saved library. Render preparation does not modify physical fields or
save a new world.

Terrain, ordinary overlays and rivers use independent reader workers. Each has
a 32 MiB raw-page cache and a 4 MiB metadata cache; helper arrays and display
buffers are additional. Complete render memory scales with the generated mesh.
The previous 192 MiB tile budget no longer describes this renderer.

Render diagnostics count retained packets, projected/displaced arrays, estimated
GPU copies, river geometry, bank texture/mipmaps and ordinary overlays. Browser
heaps, transient allocations, workers and driver overhead are additional.

## Verification

The implementation plan and acceptance criteria are in
[implementation-2.17.md](../design/implementation-2.17.md). All 275 automated tests,
typecheck and formatting checks pass. Browser checks cover both poles,
coastline/grid toggles, manual saving and the actual maximum-resolution river
regression.

The existing 2,621,442-cell world retains all 5,242,880 terrain triangles. Its
final flat-map terrain and rivers draw 9,403,321 triangles and account for
1.02 GiB of retained display buffers, excluding worker and driver overhead.
Opening it on this cloud machine's SwiftShader software GPU took 184.3 seconds;
the full-map graphics frame took 7.84 seconds and the tested close river view
581.9 ms. These are software-graphics observations, not hardware-GPU claims.
Camera movement requested no replacement terrain or river samples.
