# Atlas 2.20.0 — fewer terrain submissions

Large worlds previously submitted terrain on the far side of the globe, and
each visible physical batch required a separate indexed GPU draw. This release
adds conservative horizon culling and bounded multi-draw submissions, and removes
one unused material field. Physical terrain, rivers, cell picking and zoom detail
retain their existing geometry and appearance.

## Horizon culling

Each complete globe representation measures an interior sphere from its actual
displayed triangles. This accounts for faceted terrain, relief and categorical
cell surfaces. The sphere shrinks by numerical margins and the maximum possible
displacement of active or pending zoom patches. A terrain batch is hidden only
when its whole bounding sphere lies behind that interior sphere from the current
camera. Broad or silhouette-crossing batches remain visible.

The geometry scan happens once per representation. Camera updates inspect batch
metadata. Culling stays disabled while terrain is incomplete, on the flat map,
or when geometry, opacity, transforms or camera conditions invalidate the proof.
Existing frustum rejection still applies independently. Temporary zoom masks
compose with this visibility decision without restoring covered base triangles.

## Draw submissions and memory

Fixed terrain uses GPU-only slabs containing at most 16 consecutive packets and
65,535 vertices. Slabs upload the existing typed arrays directly, preserving
packed attributes, Uint16 indices, primitive order and per-packet visibility.
There is no merged CPU geometry. The final slab shrinks to its actual size when
loading finishes; temporary index-rebasing scratch is bounded by one packet.

Browsers with `WEBGL_multi_draw` submit each visible slab in one native call.
Without that extension, the same ranges use ordinary indexed draws. The narrow
adapter targets Three r185; other revisions and unsupported material layouts use
ordinary meshes until their compatibility is verified. Rivers, symbols, grid,
zoom patches and replacement masks retain their separate rendering paths.

The fixed physical material layout now contains five RGBA8 fields. The removed
sixth field was unused by the fixed-terrain shader. This saves four CPU bytes
and four GPU bytes per ordinary terrain vertex. The legacy sampled renderer's
six-field layout remains intact. CPU displaced positions remain available for
picking, reconstruction and other operations.

Temporary zoom masks share original CPU arrays but own disposable GPU attribute
wrappers because the original terrain is now stored in slabs. This can increase
GPU memory while a zoom patch is active. Removing or replacing the patch releases
those buffers instead of accumulating copies across visited regions. Diagnostics
account for slab capacity, scratch and the masks' temporary GPU storage.

## Verification

All 376 tests pass, along with TypeScript, repository formatting and changed-file
lint. Regression tests cover the conservative culling proof, actual adaptive
primal and categorical surfaces, packed attribute bytes and normalized formats,
Uint16 limits, draw ordering, fallback ranges and buffer disposal. The browser
checks include actual native draw calls rather than relying on Three's logical
draw counter.

Nine small-world views match the previous version pixel for pixel, including
both poles, flat map, all three map styles, manual refinement, rivers and active
zoom detail. Forced extension-free rendering matches the native path in every
view. Physical picking returns the same anchor. Browser and WebGL error checks
pass.

Additional categorical tectonics views in both projections and the analytical
elevation map match the baseline exactly, each reducing eight terrain draws to
one native call.

The retained 2,621,442-cell world gives these terrain-only results with rivers,
grid and other overlays hidden. Counts are actual WebGL calls, including native
multi-draw calls, rather than the number of logical ranges within those calls.

The maximum-world close polar and flat-map captures are pixel-identical to the
baseline. The wide globe differs at two isolated interior pixels out of
2,334,720, with a maximum channel difference of 27. There is no contiguous gap
or changed silhouette in the inspected crops. The cause of those two color
differences is not established; this view is not claimed to be pixel-identical.

The globe's 2,807,110 packet vertices save 11,228,440 CPU bytes and the same
amount of GPU storage by removing the unused field: 21.42 MiB combined, before
the new 34,816 bytes of batching scratch and draw-range arrays. Completed slabs
replace the original terrain GPU allocation exactly; they do not retain another
full GPU copy. The CPU position arrays remain present.

The small-world allocation probe confirms matching CPU and GPU savings of
43,752 bytes each in the ordinary globe view. With the tested zoom patch active,
GPU storage is 28,256 bytes above the previous version while retained CPU storage
is 200,336 bytes lower. Temporary mask ownership explains that tradeoff.
Three zoom on/off cycles return to exactly 9,080,194 allocated WebGL buffer
bytes when off and 10,679,354 when on, with no additional terrain, river or
sampling reads. Picking and retained CPU positions remain unchanged.

The maximum globe's actual allocated WebGL buffer storage is 177,456,472 bytes
after loading, with a 179,400,172-byte preparation peak. Accounted display buffers
drop from 768,463,597 to 746,041,533 bytes. The compact browser results are in
[`measurements/terrain-rendering-browser-2.20.0.json`](../../observations/measurements/terrain-rendering-browser-2.20.0.json).

Measurements use Chromium with ANGLE/SwiftShader in the cloud environment.
They establish draw submission, geometry and buffer behavior, not hardware GPU
frame rates. Native WebGL buffer measurements exclude textures, JavaScript
objects, worker heaps and driver overhead; horizon culling reduces submitted work without releasing
the resident full-detail terrain.

Application version is 2.20.0. Generator identity remains 2.17.1; saved worlds
need no regeneration and saving remains manual. No new disk cache or resolution
recomputation is introduced.
