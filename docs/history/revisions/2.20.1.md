# Atlas 2.20.1 — flow trails and categorical loading

Wind and current overlays used short dashed chords and looping point sprites.
On the globe, the chords could pass below the terrain: an overview vector's
midpoint could be more than seven kilometres below sea level despite its small
endpoint lift. Pausing removed the particles, and multiplying absolute time by
animation speed caused phase changes when controls changed.

The five categorical layers also loaded slowly on large worlds. Tectonic plates,
river basins, river sources, biomes, and marshes/peatlands share a physical dual
cell mesh. Their loader cycled several large raw field pages through the snapshot
cache for each packet, repeatedly evicting data needed by adjacent packets.

## Flow rendering

The renderer now uses one bounded draw of tessellated, fading geodesic trails.
Moving heads follow the source vector direction. Globe segments include enough
lift to compensate for their chord sag. Wind overlays remain visible over relief
and hide behind the globe; ocean currents keep terrain depth testing so land
can obscure them. Map seam and pole splits retain the original path coordinate.
Flow packets keep complete vector endpoints so a dateline split does not restart
the animation on each side.

Tails keep a readable fraction of their path while preserving a dark gap between
heads at higher densities. Slower nonzero vectors have a minimum display length
so their direction remains visible at overview scale.

An accumulated clock preserves phase through pauses, speed changes, zero speed,
replacement packets, and an off/on visibility cycle. The Flow trails toggle
controls the entire draw immediately. Density updates use a uniform and reuse
geometry. Neither animation nor density controls query new source data.

These trails interpolate the existing bounded local vectors; they do not run a
new atmospheric or ocean simulation. Geometry is capped at 512 paths and 64
subdivisions per path, with a single draw and a bounded particle-density value.

## Categorical preparation

A per-reader cache retains at most 8 MiB of decoded field blocks, each covering
32,768 rows. It leaves the existing 32 MiB raw snapshot cache unchanged and adds
no disk cache. Cell positions reuse the saved spatial index, and cell heights
reuse the exact Float32 height and lake-depth fields already read for colors.
Corner lake surfaces keep their original raw height/level/fraction calculation.
The largest decoded block is 768 KiB; gather results own their arrays, so surface
adjustments cannot mutate cached data.

Prepared terrain packets now use the next animation frame's existing 8 ms
installation budget instead of waiting for the 100 ms overlay/status interval.
Progressive preview scheduling and GPU fences still limit rendering work.

All cells, triangles, colors, provoking vertices, lake surfaces and ordering
remain intact. The categorical mesh still has three times as many triangles as
the primal terrain mesh, so completed frames can cost more on large worlds.
This correction primarily targets preparation and loading.

## Verification

- All 390 tests pass, along with TypeScript, repository formatting and
  changed-file lint.
- The reader produces byte-identical arrays for 325 complete packets across all
  five categorical layers and five seasons, including original and regionally
  refined lake worlds: 67,485,800 compared bytes.
- A 655,362-cell topology profile with a 32 MiB raw-page cache model reduces
  categorical page reads from 12,599.53 to 2,185.23 MiB, an 82.66% reduction.
  This is a page-cache model, not an IndexedDB timing measurement; actual browser
  results are recorded separately.
- Browser tests cover wind and currents in both projections, forward animation,
  paused frames, zero speed, density zero/restore, immediate hiding, and phase
  preservation through a delayed off/on cycle. Pause and density changes make
  no new overlay requests.

The maximum-world image is pixel-identical. Natural, elevation and all five
categorical layers also match exactly in the smaller comparison. The extra
bounded worker cache is outside the display-buffer count.

Measurements use Chromium with ANGLE/SwiftShader in this cloud environment.
They are observed loading comparisons, not hardware GPU benchmarks. The completed
maximum-world frame took 2.889 seconds before and 2.547 seconds after in single
observations; the main gain is preparation, and this world still takes about two
minutes to load in this environment. Large categorical views retain their full
geometry and remain demanding on software graphics.
