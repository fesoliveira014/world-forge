# v2.13.0 — generation performance and optional higher resolutions

The existing generation algorithms remain: moving crust, two climate passes when feedback is needed, four seasons, conservative moisture transport, seasonal lake storage, river shaping, minerals and fertility. This revision reduces repeated CPU work and temporary mesh allocation. It does not skip climate feedback, lower detail behind a control, or change geological durations.

## What changed

### Compile fixed transport coefficients once per season

For each shared edge, let `F` be signed area flux in m²/s, `K` the existing mixing conductance in m²/s, and `A`, `B` the two physical cell areas. Compile:

```text
forwardRate = (max(F, 0) + K) / A
reverseRate = (max(-F, 0) + K) / B
exchange = dt × (forwardRate × inventoryA − reverseRate × inventoryB)
deltaA -= exchange
deltaB += exchange
```

This algebraically combines the former upwind advection and separate diffusion exchanges. Both rates are inverse seconds. Every edge reads the previous inventory, and the accumulated changes are applied only after all edges. Evaporation and precipitation follow transport as before. Ocean heat uses the same operator with zero mixing and permits negative heat inventories. There is no new positivity clamp that could manufacture water.

`computeStableTimeStep` retains the original 0.65 CFL factor and the original outgoing advection-plus-diffusion bound. Fluxes and conductances remain double precision. Operators belong to a single season and are not cached across changed winds or ocean masks. Floating-point operation order differs slightly from the older split exchanges; conservation and output comparisons accompany the change.

### Reuse geometry and isolate the atmosphere loop

Physical areas, terrain gradients, distance to land and reference-land distance are computed once per climate pass. The four seasonal solves reuse them; the final climate pass rebuilds them after terrain changes. Ocean heat relaxation reuses its fixed baseline inventory.

The frequently repeated atmosphere exchange loop is now a small, allocation-free function separate from the large seasonal setup. It keeps the original evaporation, saturation and precipitation order. It holds each cell's working inventory in local variables and updates the same full water ledger. Rainout coefficients for partial steps at the spin-up boundary and simulation endpoint are calculated outside the hot cell loop. The spin-up and measurement durations remain unchanged.

### Allocate mesh data directly

Cell coordinates are allocated at the known final size `3 × (10 × 4^level + 2)`. Each subdivided triangle buffer is allocated at exactly four times its parent's size. This removes the large growing JavaScript coordinate/triangle arrays and their simultaneous typed-array copies. Vertex numbering, face order, jitter random draws, edge legalization and geometry are preserved. The existing undirected numeric edge keys remain exact at level 9 because the maximum key is below `Number.MAX_SAFE_INTEGER`.

## Measured generation time

All times are local Node.js 24.19 measurements, not browser or low-end-device guarantees. The full AETHER-0004 comparison uses identical saved settings, terrain level 8 and process level 6. Both runs used the same CPU-profiler settings. The ordinary default pair ran sequentially in separate fresh Node processes without the profiler or competing generation jobs. Times include the generator pipeline but exclude rendering, serialization, file writes and browser startup. Single-run timing varies by machine and system load.

| Recipe / stage | Before | Revised | Time reduction |
| --- | ---: | ---: | ---: |
| Default AETHER-2408, levels 5/5 | 19.39 s | 12.81 s | 34.0% |
| Default, both climate passes | 14.06 s | 7.52 s | 46.5% |
| AETHER-0004, levels 8/6 | 225.88 s | 134.14 s | 40.6% |
| AETHER-0004, both climate passes | 170.14 s | 84.57 s | 50.3% |
| AETHER-0004, surface grid | 10.30 s | 7.83 s | 24.0% |

The CPU profile identified atmosphere exchange and shared-edge transport as the dominant work. The first rate-compilation pass reduced AETHER-0004 to 146.97 s; the final smaller atmosphere loop reduced it further to 134.14 s. An initial default comparison overlapped a high-detail job and used both module copies in one process; its noisy result was discarded in favor of the isolated fresh-process pair above.

AETHER-0004 retained **564,799,564 bytes** in both revisions (538.63 MiB). These changes primarily reduce CPU work and temporary mesh allocation; they do not shrink the saved world's field set. Temporary compiled rates add two double-precision values per process-grid edge. Browser rendering and GPU memory are additional.

## Numerical checks

The revised AETHER-0004 fields were compared against the retained v2.12.0 snapshot from the same recipe and source as the fresh timing baseline. **All 3,540 typed arrays matched exactly**, including rebuilt surface geometry, climate, terrain, water, rivers, ecology and fertility. The representation changes do not promise bitwise equivalence for every seed: the fused edge arithmetic may round differently before Float32 output.

The only changed scalar in the comparison was the last few floating-point digits of the atmosphere residual (`2.8678929e-11` → `2.8679055e-11`). The full-world atmosphere relative residual was about `2.87e-11`, and the land-water residual was unchanged. Lake count remained 3,468 and deposit count 240. The existing suite plus a focused reverse-flow/mixing case gives **34 passing tests**. The added case covers unequal physical areas, a shortened step, CFL positivity, total inventory and negative heat. TypeScript checking and the production build pass.

Raw timings and comparison results are in [observations/performance](../../observations/performance/final.json). The before/final records, isolated default pair and highest-detail checks are retained alongside it. Earlier images and observations describe their original releases.

## New resolution limits

| Setting | Previous maximum | New maximum | Default |
| --- | ---: | ---: | ---: |
| Surface terrain | Level 8 · 655,362 cells | Level 9 · 2,621,442 cells | Level 5 · 10,242 cells |
| Climate and plates | Level 6 · 40,962 cells | Level 7 · 163,842 cells | Level 5 · 10,242 cells |

The surface selector, simulation slider and project-file validator accept the new limits. Simulation detail still cannot exceed surface detail. v2.12.0 and earlier accepted recipes remain importable.

A complete **terrain 9 / process 3** AETHER-0004 run finished in 139.82 s with finite fields, 5,384 reservoirs and a sphere-area error of `3.64e-13` steradians. It retained **2,141,154,018 bytes** (about 1.99 GiB) of typed data, with about 2.84 GiB peak Node resident memory. Its coarse climate makes it a terrain-capacity check, not a prediction of the runtime at both maximum settings.

The **process 7** check built all 163,842 cells and executed 30 wind-and-mixing steps at the computed CFL limit, including a shortened final step. Inventories stayed nonnegative and finite, and relative conservation error was `4.79e-15`. This was a grid/operator check, not a full generation at process 7. The simultaneous 9/7 combination and interactive browser rendering at that size were not timed.

Each subdivision quadruples cell count. Climate can cost substantially more than four times as much because stable transport steps also get shorter. The new maxima are optional for machines with ample RAM and patience; keeping simulation detail lower remains the useful way to add surface detail without a large climate cost. Existing defaults stay unchanged.

## Reproduce timings

```sh
npm run measure
npm run measure -- examples/AETHER-0004.json
npm run measure -- examples/AETHER-0004.json 9 3
```

The optional arguments override surface and process subdivision respectively. The measurement helper emits configuration, per-stage time, retained typed-array bytes and model residuals. It does not enforce machine-specific performance gates or retain full world snapshots.
