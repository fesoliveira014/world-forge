# Atlas 2.16.2 — manual saving and clearer paged detail

Generated worlds remain unsaved until **Save world** is selected. The paged viewer
also samples natural and illustrated materials more densely, corrects polar
texture coordinates, and restores useful coastline and cell-grid overlays.
These changes preserve the stored simulation fields and physical evolution.

## Save only the worlds you choose

Generation, recipe import and regional refinement prepare temporary IndexedDB
pages for viewing. They do not add entries to **Saved worlds**. The page retains
a small handle and bounded caches; it does not keep the complete simulation in
memory merely because the world is unsaved.

**Save world** names the current draft and atomically adds its existing pages to
the library. It does not rerun generation, restore the physical graph, or duplicate
its numerical buffers. Failed or cancelled saves leave the draft readable. A
failed generation or refinement leaves the previous view intact.

Replacement and tab cleanup remove only owned, unsaved drafts. A late cleanup
cannot delete a world whose Save has committed. Browser Web Locks protect drafts
in other active tabs and let later sessions reclaim abandoned drafts. Browsers
without Web Locks still remove explicitly discarded drafts, but skip automatic
cleanup of unknown owners because another tab may be using them.

Database version 3 keeps temporary descriptors separate from the saved catalog.
Existing 2.16 saved worlds remain saved, including descriptors created before the
`saved` flag existed. Saved worlds remain local to this browser and site; recipe
export is separate and contains reconstruction instructions rather than a complete
physical snapshot.

## Dense materials with fixed limits

Natural, Shaded relief and Ink atlas now sample material fields independently of
the 17 × 17 terrain geometry vertices. Progressive rectangular material maps
resolve more of the saved coast, vegetation, wetland, snow and lake variation
without increasing the physical cell count. Shared dyadic samples, stitched
material borders and parent blending preserve continuity while detail arrives.

Each tile uses six RGBA8 material maps. Elevation, temperature and incision use
two channels each; fraction fields use one channel. This is bounded display
quantization. Inspection and physical simulation retain their original values.
The reader still interpolates the original Float32 vertex attributes in their
original arithmetic order; deduplicating repeated source rows changes lookup
cost, not the returned field values.

Material requests contain at most 16,384 sample directions. Supported map axes
have 17–257 samples, with at most 32,768 intervals per tile. Tile storage is capped
at **192 MiB** of accounted CPU/GPU data, including material maps and reserved
geometry-transition buffers. The limits remain 64 active tiles, 128 resident
tiles and four concurrent tile requests. Terrain and inspection use one reader
worker; a second reader starts lazily for overlays so a slow overlay query cannot
block terrain loading. Each reader has a 32 MiB raw-page cache and 4 MiB metadata
cache: with both active, those budgets total 64 MiB and 8 MiB respectively.
Bounded spatial/material helper caches, overlay packets, the browser runtime and
driver allocations are additional; this is not a total-process memory limit.
Generation, indexing and regional refinement still need the full physical state
in a compute worker.

The first four tiles reuse their existing 17 × 17 samples for initial coarse
coverage, then refine into denser child materials. Lighting normals derive from
the dense physical height field and geographic tangents, removing coarse-triangle
facets without changing terrain displacement.

Globe texture coordinates now follow the interpolated spherical direction. This
removes longitude distortion across collapsed polar triangles. Categorical maps
retain nearest filtering and geographic ownership; the map and globe share the
same saved fields.

River preparation gathers course metadata and points in bounded batches and
retains each selected clipped path once. A 6,150-course regression needs fewer
than 1,000 numeric reads; 36 old/new packet comparisons remain byte-identical.
This avoids the previous repeated per-reach reads.

## Coastlines and the physical cell grid

Natural and art styles draw the optional coastline directly from the continuous
ocean-coverage field. It follows connected-ocean coverage rather than applying a
new terrain-height threshold. Diagnostic layers use connected physical coastline
paths with bounded simplification; reducing detail preserves complete paths
instead of scattering unrelated tiny edge fragments.

The vector fallback reads existing ocean-boundary edge references, so old saved
worlds need no new coastline index. A query retains at most 262,144 physical edges
and scans at most 16,777,216 index values in chunks of 8,192; its per-reader cached
edge-ID lists also cap at 262,144 entries. Working topology is additional to the
tile budget. Exceeding these hard bounds requests a closer view rather than
returning disconnected fragments. The final overlay packet still contains at
most 8,192 segments shared among its enabled line layers.

The cell grid walks connected physical cells intersecting the viewport and draws
each visible edge once. When the complete visible grid exceeds the geometry
budget, **Cell grid: zoom in to see individual cells** explains the missing lines.
Zooming in restores the complete local grid. This replaces the previous sample
of at most 128 isolated cells, which was nearly invisible on large worlds.
Toggles immediately hide existing overlay groups and apply current flags to late
responses, so a slow packet cannot restore disabled lines. Overlay lines remain clipped to the map and globe horizon so raised display
terrain does not bury them or reveal the far side of the planet.

## Verification and measurement scope

Storage regressions cover real IndexedDB transactions, promotion/cancellation
races, failed-save recovery, active-tab protection, interrupted draft cleanup,
and exact restoration of a version-2 database. The actual generation-worker
protocol is exercised for generation, import, refinement and explicit promotion.
Grid regressions compare complete output against every intersecting physical
edge in regional, dateline and polar views, and check bounded work for dense
overviews. Material tests cover shared borders, coordinate continuity,
quantization bounds, categorical filtering and field parity.

The [saved-field audit](../../observations/measurements/saved-field-fidelity.json) checked 12,090
queries across five seasonal views on a generated 10,242-cell world and found
zero differences in the audited material fields. It is not a 2.6-million-cell
browser measurement. The [dense-query profile](../../observations/measurements/dense-material-query.json)
uses a synthetic 163,842-site grid and in-memory page reads; it verifies identical
returned buffers and bounded query allocations, not IndexedDB latency or GPU
frame rate. The [full-world browser check](../../observations/measurements/high-resolution-rendering-2.16.2.json)
reopens the exact same 2,621,442-cell saved world before and after the fix at
2048 × 1140. The settled map has 536,640 material samples independently of
18,496 shape samples, with 51,952,800 bytes of accounted tile storage and no
visible coarsenings. The old 12-pixel coastline blocks are absent.

Cold maximum-resolution loading remains expensive in the cloud software renderer:
the complete material view settles in about 5.6 minutes, and its first global
river packet takes about 3.5 minutes. Terrain now appears progressively while
the independent overlay worker runs. These timings include the initial globe
queries before switching to the map and are not steady-state frame rates.
